# claude-learning

Hands-on projects built while preparing for Claude certification. Each topic
lives in its own numbered folder and is self-contained.

| Folder | Topic | What it covers |
|--------|-------|----------------|
| [`01-multi-tool-agent-loop`](01-multi-tool-agent-loop) | Multi-Tool Agent Loop | Agentic loop lifecycle on the Messages API; `stop_reason` as the authoritative loop-control signal; `tool_use` / `end_turn` handling; appending tool results to history; safety iteration caps done right. |
| [`02-hub-and-spoke-research-coordinator`](02-hub-and-spoke-research-coordinator) | Hub-and-Spoke Research Coordinator | Centralised coordination through a hub; subagent isolation and explicit context passing; broad vs narrow task decomposition; iterative refinement loops for coverage gaps; tracing failures back to coordinator decomposition. |
| [`03-structured-metadata-context-passing`](03-structured-metadata-context-passing) | Context Passing with Structured Metadata | `allowedTools` must include `Agent`/`Task`; separating content from source attribution; why stripped metadata causes downstream attribution errors; parallel subagent spawning for latency; `fork_session` vs parallel Task calls. |
| [`04-prerequisite-gate-financial-ops`](04-prerequisite-gate-financial-ops) | Prerequisite Gate for Financial Operations | Programmatic enforcement vs prompt-based guidance for financial ops; prerequisite gates that physically block a tool call until preconditions are met; structured handoff protocols with all required fields; decomposing and parallel-handling multi-concern requests. |
| [`05-agent-sdk-hooks-normalization-policy`](05-agent-sdk-hooks-normalization-policy) | Agent SDK Hooks for Normalisation and Policy Enforcement | PostToolUse (after execution, normalise) vs PreToolUse (before execution, enforce); hooks vs prompts for 100% requirements; normalising 3 heterogeneous MCP tool formats to one schema; threshold- and prerequisite-based PreToolUse blocking. |
| [`06-multi-pass-code-review-pipeline`](06-multi-pass-code-review-pipeline) | Multi-Pass Code Review Pipeline | Attention dilution across files in single-pass review; per-item + cross-item multi-pass architecture; fixed sequential vs dynamic adaptive decomposition; why batching without a cross-file pass still misses cross-cutting issues; identifying dilution artefacts (same pattern flagged in one file, approved in another). |
| [`07-session-management-strategies`](07-session-management-strategies) | Session Management Strategies | resume vs fork_session vs fresh start with summary injection; the stale-context problem after file changes; structured summaries that preserve knowledge without stale tool results; targeted re-analysis vs full re-exploration. |
| [`08-tool-descriptions-eliminate-misrouting`](08-tool-descriptions-eliminate-misrouting) | Tool Descriptions That Eliminate Misrouting | Descriptions as the primary tool-selection signal; production-grade descriptions (purpose, inputs, examples, edge cases, boundaries); diagnosing misrouting from ambiguous/overlapping descriptions; system-prompt keyword conflicts that override good descriptions. |
